MAPS ko pii 적용 가능성 검증 결과

검증일 2026년 11월 5일 · 제출 기준 2026년 11월 6일 금요일 · 기존 검토의 후속 시험

결론은 조건부 적용 가능입니다. 개인정보 컬럼을 정해 처리하는 CSV·JSON 마스킹에는 활용할 수 있습니다. 상담 자유문장은 이름과 비정형 표현이 남아, 자동 처리 결과를 그대로 사용하기에는 보완이 필요합니다.

이번 산출물은 상담 텍스트, CSV·JSON 처리, 미탐·오탐과 잔존값, 적용 판단의 네 가지로 한정했습니다. 모든 시험값은 합성 데이터이며 실제 MAPS 고객 원문으로 측정한 성능은 아닙니다. 논문 구현, 별도 모델 개발, 전체 파이프라인 통합은 수행 범위에 포함하지 않았습니다.

1 상담 구어체와 텍스트 시험

ko-pii 1.22.17을 실제 내려받아 Windows의 Python 3.12.14에서 실행했습니다. 처리 전략은 redact이며, 기본 시험은 STRICT입니다. 상담 구어체 10건을 포함한 개인정보 표현 사례 43건과 개인정보 없는 문장 10건, 총 53건을 사용했습니다. 정답으로 표시한 개인정보 구간은 53개이며 13개 라벨을 확인했습니다. 전화·이메일·주민등록번호·외국인등록번호·카드·계좌·이름·주소·생년월일·여권·차량·면허·IP의 13개 라벨만 선택했으며, 전체 라벨의 성능을 평가한 것은 아닙니다. 상담 문장은 직접 작성한 텍스트이며 녹음·STT 시험은 아닙니다.

구분정상 탐지미탐오탐원문 전체가 남은 정답 구간
STRICT 전체 53건39/5314515/53
그중 상담 구어체 10건10/18828/18
PARANOID 전체 53건 비교39/5314512/53

정상 탐지와 미탐은 라벨·시작·끝 위치가 모두 일치하는 정답 구간 단위로 계산했습니다. 오탐은 정답에 없는 탐지 구간 수입니다. 정탐과 미탐의 합은 53이며, 오탐은 별도로 셉니다. 원문 전체 잔존은 정답 문자열이 출력에 그대로 남은 수로, 일부만 가렸더라도 안전하다고 판단하는 지표는 아닙니다.

2 CSV와 JSON 개인정보 컬럼 시험

동일한 합성 상담 레코드 8행을 실제 CSV와 중첩 JSON 파일로 만들고 다시 읽어 처리했습니다. 이름·전화·이메일·주소·생년월일·계좌번호의 6개 컬럼에서 빈값 2개를 제외한 46개 셀을 비교했습니다.

파일과 처리 방식비교한 값원문이 남은 셀시험 결과
CSV 헤더 자동 매핑4622전화·생년월일·계좌 컬럼이 매핑되지 않음
CSV 컬럼 명시460지정한 6개 컬럼의 전체값 치환
JSON 문자열 자동 탐지4627짧은 이름·문맥 없는 값 등의 누락
JSON 필드 라벨 명시460지정한 6개 컬럼의 전체값 치환

명시 매핑은 customer_name→PERSON, phone_number→PHONE, email→EMAIL, address→ADDRESS, birth_date→DT_BIRTH, account_number→ACCOUNT입니다. 이는 컬럼이 개인정보라는 사실을 호출자가 지정한 결과이며 자동 탐지 정확도가 100%라는 뜻은 아닙니다.

네 가지 출력 모두 행·컬럼 구조를 유지했습니다. 입력 객체와 CSV·JSON 파일의 처리 전후 해시도 같았습니다. 별도 JSON 시험에서 정수형 식별값은 자동 탐지로 보존됐고, 필드 라벨을 명시하면 문자열 마스킹값으로 바뀌었습니다. null은 유지됐습니다. 잘못된 필드 경로와 개인정보 필드의 bool·float 입력은 세 사례 모두 오류로 거부됐습니다.

0건 잔존은 지정한 6개 컬럼에만 해당합니다. 비매핑 policy_id는 네 출력에 모두 남았습니다. CSV 표 API는 비매핑 consultation_note를 그대로 보존했습니다. 따라서 이 출력 파일 전체를 개인정보가 제거된 파일로 취급해서는 안 됩니다. JSON도 메모의 문자열을 탐지하지만 미탐이 가능하고, 키·숫자값까지 자동으로 보호하지는 않습니다. 구조화 처리 안내

PARANOID는 전체 원문 잔존을 15개에서 12개로 줄였지만, 주소 일부만 성명으로 치환한 사례가 있었습니다. 정답의 문자 범위가 전부 가려지지 않은 구간은 14개였습니다. 개인정보 없는 설명문 10건 중 STRICT는 0건, PARANOID는 1건의 본문을 바꿨습니다. 모드 변경만으로 상담 문장의 누락을 해결할 수 없습니다.

정답은 시험 전에 코드에 표시했으며, 위 결과에 맞춰 탐지 규칙이나 제외어를 조정하지 않았습니다. 소수의 사람이 작성한 시험이므로 실서비스 탐지율이나 실제 고객 데이터에 대한 성능을 보장하지 않습니다. 동일 이름·번호가 여러 사례에 반복돼 독립 표본으로도 볼 수 없습니다. 공식 평가 안내도 탐지 위치 평가와 마스킹 후 잔존값을 구분합니다. 평가 안내

4 MAPS 적용 가능 여부

적용 대상판단필요한 보완
CSV·JSON의 확정된 개인정보 컬럼조건부 적용 가능실제 컬럼명과 라벨을 명시하고 지정 누락 검사
상담 자유문장 자동 마스킹보완 후 재검증짧은 이름·조사·영문명·구어 숫자·비정형 주소 확인
계약번호 등 사내 식별자와 민감한 상담 내용별도 처리 기준 필요자동 탐지 범위로 가정하지 말고 명시 마스킹 또는 입력 제외
MAPS 운영 전체 보호이번 검증으로 확정 불가실제 서비스 권한·로그·이관 동작은 별도 통합 시험

우선 확정된 개인정보 컬럼을 명시해 마스킹하는 방식으로 사용하고, 상담 자유문장에는 검토 절차를 두는 것이 적절합니다. AI에 필요하지 않은 원천값·상담 원문은 입력에서 제외하는 방안을 우선 적용합니다. 이 판단은 이번 합성 시험 결과에 따른 제안입니다.

MAPS 화면설계 v0.9의 원본 이관 유지 요구와 보안 테스트 SEC-031~034를 고려하면, 화면·AI 입력에 제공하는 사본을 가리고 이관 원본은 별도로 유지해야 합니다. 이번 시험은 입력 원본을 바꾸지 않는지 확인했으며, 실제 Gold·대상 DB에 대한 이관 시험은 수행하지 않았습니다. 기존 담당자의 최신 코드와 동일한 시험이 이미 끝났는지는 확인하지 않았으므로, 이 결과를 기존 검토에 추가할 검증 기록으로 공유하면 됩니다.
