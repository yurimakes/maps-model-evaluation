# 공통 평가 계약

이 작업은 기존 모델을 새로 학습·추론한 것이 아니라 저장된 예측을 동일한 산식으로 다시 채점했다. 기존 생성 코드와 과거 지표는 수정하지 않았다. 신규 실험도 같은 `evaluation.metrics.summarize`와 `evaluation.contract.validate`를 사용하고, 새 입력·예측·설정·모델 revision·실행 시간·오류를 새 결과 디렉터리에 기록한다.

## 분모와 정답

- 질문 단위는 `system|table|column`이다. 같은 이름의 다른 테이블 컬럼은 다른 질문/Target이다.
- 정답·예측은 `TABLE.COLUMN` 집합이다. 이관 제외/보류는 빈 집합으로 표현한다. 중복·누락 질문, 중복 후보, 범위 밖 후보, 스냅샷과 다른 정답은 실패 처리한다.
- mapping precision/recall/F1은 전체 질문의 정답 쌍 기준 micro TP/FP/FN으로 계산한다. 제외 질문의 잘못된 추천도 FP다. 복수 정답 중 하나만 회수하면 나머지는 FN이다.
- Top-K hit rate는 양성 질문 중 상위 K개에 정답이 하나 이상 있는 비율이다. pair recall@K는 전체 정답 쌍 중 회수한 비율이다. 두 값은 서로 다르다.
- decision accuracy는 양성에서 하나 이상의 올바른 추천, 음성에서 보류한 비율이다. exact set accuracy는 정답 집합 완전 일치율이다. 모호한 단일 `accuracy` 열을 쓰지 않는다.
- 추천을 보류했어도 후보 순위 Top-K는 별도로 측정한다. 순위 개선을 자동 매핑/승인 개선으로 해석하지 않는다.
- 실패·INVALID·미실행은 보류 정답으로 바꾸지 않는다. 현재 등록된 CSV는 성공적으로 저장된 예측만 포함한다. 앞으로 실행 오류가 있으면 오류율을 별도로 기록하고 현 계약에 억지로 넣지 않는다.

## 등록한 범위

| 등록 평가 | 질문/양성/정답 쌍 | 후보 | 성격 |
|---|---|---|---|
| graph-114 | 114 / 65 / 68 | 78 | outer/inner 원천별 분리 |
| legacy-local-114 | 114 / 65 / 68 | 78 | 당시 로컬 실험, graph의 공통 기반 |
| benchmark-114 | 114 / 65 / 68 | 78 | 최신 로컬 규칙·이력 탐색 |
| phase2-model-93 | 93 / 44 / 44 | 전체 25, 질문별 11 또는 14 | 실제 임베딩·Magneto 모델의 저장 결과 |
| homepage-new-model-18 | 18 / 14 / 14 | 민원 14 | 새 모델 결과의 공통 18질문 부분집합 |
| homepage-historical-replay-18 | 18 / 14 / 14 | 민원 14 | 과거 RAG 출력의 첫 반복/30회 최빈값 |

앞의 세 평가는 정답·스키마 입력·후보·프로토콜 지문이 같아 공통 comparison_key를 공유한다. 나머지 세 그룹은 각각 다른 키를 사용한다. 18질문×30회를 540개 독립 표본으로 세지 않는다. 서로 다른 키를 하나의 순위표로 합산하지 않는다. 같은 키도 공정 비교의 필요조건이며, 실행 환경·튜닝 예산·공개된 표준사전의 설계 영향까지 자동으로 같다는 증거는 아니다.

`comparison_key`는 질문별 정답, 질문별 허용 후보, 스키마·사전 입력의 의미 지문, 평가 프로토콜로 만든다. 로컬 파일 경로나 로그 차이는 입력 지문에서 제외한다. 모델 방식이 바뀌어도 공통 채점은 그대로 사용하고 프로토콜/입력이 달라지면 키가 바뀐다. 기존 CSV에 함께 있던 과거 RAG 행은 별도 registry 항목으로 분리하며 누락하지 않는다.

## 재현 수준

공통 재채점은 Python 표준 라이브러리만 필요하다. 기존 알고리즘 검사는 각 실험의 requirements 환경을 사용한다.

```powershell
python -X utf8 tools/validate_local.py --packages "기존 Python 3.13 라이브러리 폴더"
```

그래프 검증은 과거 verification.json을 덮어쓰지 않도록 새 검증 폴더의 복제본에서 실행한다. 최신 benchmark의 테스트는 32개이며, API 클라이언트 테스트는 ScriptedClient/주입 sender를 사용한다. Azure 실호출이나 모델 가중치 재추론은 하지 않았다.

원래 그래프의 저장 DB에는 정답 연결이 포함되어 있다. 평가 구현은 보류 원천 정답을 제외한 별도 그래프를 구성하며, 정답을 바꿔도 점수·임계값이 같은 10조건을 재검사했다. 새 재채점 자체가 이 학습 분리를 증명하는 것은 아니다.

검색 후보 진단, 근거 참조 프록시, scripted validation은 기존 `phase2_report.html`에 그대로 남겼고 새로운 end-to-end F1 순위표에는 넣지 않았다. AI-Hub 분류처럼 다른 과제도 같은 스키마 매핑 점수와 합산하지 않는다. 프로젝트 자료를 보고 설계한 방법이라 외부 미관측 데이터의 독립 성능은 아직 확인되지 않았다.
