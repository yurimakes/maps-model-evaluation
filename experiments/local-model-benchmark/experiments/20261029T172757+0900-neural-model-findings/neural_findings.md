# 실제 모델 비교 · 판단

우선 방향은 **메타데이터 보강 + 다국어 E5 후보 보완 + 기존 2차 최종 검증 유지**다.

## 동일한 홈페이지 18질문

| 방법 | 정밀도 | 재현율 | F1 | 정확도 |
|---|---:|---:|---:|---:|
| 2차 저장 출력 · 고정 설정 rep=1 | 100.0% | 85.7% | 92.3% | 88.9% |
| Magneto + 다국어 E5 + 메타데이터 | 92.9% | 92.9% | 92.9% | 88.9% |

F1 차이는 0.55%p이며 정밀도는 -7.14%p다. 문항 단위 부트스트랩의 F1 차이 95% 구간은 -10.98~11.94%p다. 같은 개발 문항의 참고 분석이고 새로운 원천에 대한 통계 검증이 아니다.

## 달라진 두 판단

- COMPLAINT_TP: 정답 COMPLAINT.CMPL_TYPE_CD, 기존 제외 → E5 COMPLAINT.CMPL_TYPE_CD
- PRODUCT_GB: 정답 제외, 기존 제외 → E5 COMPLAINT.PRD_ID

## 전체 93질문에서의 방향

- 공식 Magneto MPNet은 컬럼명만 쓸 때 F1 43.2%, 설명·자료형을 추가하면 65.2%였다. 먼저 메타데이터를 제대로 활용할 필요가 있다.
- 같은 메타데이터 조건의 다국어 E5는 F1 65.9%로 MPNet 65.2%와 차이가 작았다. CPU 매핑 단계 시간은 E5 약 3.1초, MPNet 약 17.2초였다. 다운로드·로드·별도 공통입력 벡터 비교는 제외한 관측 시간이다.
- 한국어 SRoBERTa의 Magneto 메타데이터 조건 F1은 40.9%였다. 한국어 문장 유사도 모델이라는 이유만으로 스키마 매핑 모델로 선택할 근거는 없다.
- E5가 COMPLAINT_TP의 누락을 보완했지만 PRODUCT_GB를 PRD_ID로 잘못 제안했다. 상담 분류·상품 구분·식별자 간 코드/업무관계 검증과 HITL을 유지해야 한다.
- 기존 2차 전체 93질문의 최종 출력은 없고, 새 Azure LLM 추론도 하지 않았다. 93질문에서의 로컬 점수를 기존 2차 전체 성능과 직접 비교하지 않는다.

실제 세 모델 추론, 공식 Magneto 기본 비LLM 모드, 실패·성공 로그와 모델 리비전·해시를 비공개 저장소에 보존했다.
