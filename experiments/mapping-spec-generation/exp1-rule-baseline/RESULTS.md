# 실험 1 결과 기록 (exp1-baseline-1.0.0)

이 문서는 비공개 입력으로 실행한 결과의 **집계값만** 기록한다. 실제 Source·Target 식별자, 시스템명, 원본 파일 해시, 행 단위 출력은 포함하지 않는다.
**정답(기존 승인 매핑) 대조는 실시하지 않았다.** 아래 수치는 정확도가 아니다.

## 1. 실행 조건

| 항목 | 값 |
|---|---|
| 알고리즘 버전 | exp1-baseline-1.0.0 (설정값은 실제 입력 실행 전에 고정) |
| 실행 환경 | CPython 3.12.3, Linux, numpy 2.4.4, scikit-learn 1.8.0 |
| 외부 API·네트워크·DB | 사용하지 않음 |
| 제외 규칙 입력 | 없음 (따라서 EXCLUDE 경로 미사용) |
| 입력 파일 변경 | 실행 전후 SHA-256 동일 |

## 2. 입력 개요 (비공개 입력)

| 항목 | 값 |

| Target 행 | 78 (테이블 10개) |
| 실제 물리 테이블명이 가정된 Source 행 | 32 |

## 6. 검증 결과

| 검증 | 결과 | 의미 |
|---|---|---|
| 합성 단위 테스트 | 28/28 통과 | 기능·판정 경로·결정성 확인 (합성 데이터, 성능 점수 아님) |
| 독립 구조 검증 | 21/21 통과 | 출력 규격 충족. 매핑 정확도와 무관 |
| 매핑 쌍 F1 | 미측정 | 정답 대조 미실시 |
| 이관 여부 일치도 | 미측정 | 정답 대조 미실시 |
| 변환 실행 정확도 | 미측정 | 값 샘플·기대 출력 없음 |
| 전문가 수용률 | 미측정 | 검토 미실시 |

해석 주의:
- 자동 MIGRATE 4건은 승인된 매핑이 아니라 업무 승인 전 초안이다.
- REVIEW 136건을 알고리즘이 맞힌 정답으로 간주하지 않는다. 보류가 많다는 것만으로 실패라 단정하지도, 확정률이 낮아 안전하다고 주장하지도 않는다.
- 설계자 관찰(미검증): "Target 식별·변환 보류" 8건 중 일부는 Source와 다른 업무 엔터티의 Target으로 연결된 것으로 보인다. 이 범주를 매핑 쌍 평가에 포함하면 정밀도가 낮아질 수 있다.

## 7. 실행 이력과 재현 확인

| 시점 | 내용 |
|---|---|
| 최초 실행 1회차 | 생성 140건, 구조 검증 20/21. 하드코딩 검사기가 실행 기록의 환경 키 문자열 하나를 입력 컬럼명과 같은 문자열로 탐지(오탐). 해당 키 이름만 변경 |
| 최초 실행 2회차 | 구조 검증 21/21. 매핑 출력 3개 파일의 해시가 1회차와 동일함을 확인(매핑 로직 불변) |
| 합성 테스트 개발 중 | 28개 중 1개 실패: 후보가 없는 행에서 "설명 없음" 사유가 기록되지 않는 버그. 수정 후 28/28 (판정 결과 자체는 동일) |
| 보존·재현 확인 | 보존된 코드 사본을 원본 입력에 다시 실행. 테스트 28/28, 구조 검증 21/21, MIGRATE 4 / REVIEW 136 / EXCLUDE 0. `mapping_draft.json`, `candidates.csv`, `decision_trace.csv`, `report.txt`, `validation_result.json`이 최초 실행 출력과 바이트 단위로 동일 |

재현 확인의 한계: 최초 실행 기록에는 출력 파일 해시만 있고 코드 파일 해시가 없었다. 따라서 코드 파일이 최초 실행과 바이트 단위로 같다는 것은 직접 증명되지 않았고, "같은 입력에서 같은 출력을 낸다"는 기능적 동일성으로 확인했다.
