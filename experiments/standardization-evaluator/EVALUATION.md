# 07.8.1 표준화 평가항목·가중치·Evidence 기준서

버전 1.0 · 작성 2026-11-06 · 담당 작업: 최유리 / AI팀

## 목적과 현재 범위

공공표준 사전과 행정안전부 문서로 지식데이터를 구축하고, 이를 바탕으로 생성한 표준화 결과를 어떤 항목·근거로 평가할지 정의한다. **이 기준서의 작성은 완료했다.** 실제 표준화 결과의 승인, 지식데이터 구축 완료, 업무 의미 정확도 확보를 뜻하지는 않는다.

현재는 공공표준의 등록 명세·명명 규칙·신규 후보의 근거를 점검한다. 2차 승인 이관자료와의 비교는 참고 분석으로 유지한다. 원천 컬럼의 업무 개념을 올바르게 해석했는지는 추후 업무 설명·코드표 등을 활용한 LLM 추천과 별도 정답 평가에서 다룬다.

## 1. 평가항목과 판정 기준

| ID | 평가항목 | 평가 단위·확인 내용 | 판정 / 구현 상태 |
|---|---|---|---|
| P01 | 표준단어 명세 | 제공된 컬럼·구성 순번별 단어명+약어가 공공사전의 단일 명세와 같은지 | 자동 점검 구현 |
| P02 | 표준용어 명세 | 제공된 컬럼별 용어명+약어가 공공사전의 단일 명세와 같은지 | 자동 점검 구현. 정의·구성단어·도메인 연결은 P04에서 검토 |
| P03 | 표준도메인 명세 | 제공된 컬럼별 도메인명+타입+길이+소수점 길이가 같은지 | 자동 점검 구현. 실제 값 범위·변환 안전성은 별도 |
| P04 | 신규 후보·구성 규칙 | 사전 검색·중복 검토, 구성단어·형식단어·도메인, 정의·영문명·약어, 신규 필요 사유 | 검토 기준 정의 완료. 현재 코드의 자동 의미 판단 범위에는 포함하지 않음 |
| P05 | Evidence·버전 | 입력·사전·문서 출처, 모델·프롬프트·검색·평가 버전과 실행 조건을 추적할 수 있는지 | 입력·사전·평가기준 해시 자동 저장. 생성 단계 기록은 별도 확인 |

표준코드·컬럼 연결의 의미 정확도는 제공된 공공 단어·용어·도메인 사전만으로 정답을 만들 수 없으므로 현재 자동 점검에서는 '범위 밖'이다. 코드값의 앞자리 0과 원천 시스템 구분은 보존한다. 현 도구는 제공된 출력 행을 점검하므로, 출력에서 통째로 누락된 원천 컬럼의 재현율을 계산하지 않는다.

### 자동 점검의 상태

- **명세 일치:** 선택한 이름에 단일 유효 사전 명세가 있고 비교 필드 전체가 같다.
- **명세 불일치:** 단일 사전 명세는 있으나 비교 필드가 다르다.
- **미등록 후보:** 현재 사전에 이름이 없다. 신규·별칭·폐기 여부를 확인하며 자동 오답이나 승인으로 처리하지 않는다.
- **사전 충돌:** 같은 이름에 복수 명세가 있다. 판정을 보류한다.
- **후보 없음:** 제공된 평가 행의 AI 답이 비어 있다. 별도로 보고한다.
- **범위 밖:** 공공사전으로 판단하지 않는 컬럼 연결·업무 코드 대응이다.

사전의 폐기 행은 유효 명세에서 제외한다. 비교는 문자열·구조 기준이며 대소문자·공백·앞자리 0을 임의로 바꾸지 않는다. 동일 평가 키가 중복되면 실행을 중단한다.

## 2. 가중치와 지표

P01~P03은 **같은 영역 안에서 각 대응 1건에 동일 가중치**를 적용한다. 단어·용어·도메인은 평가 단위가 다르므로 영역 간 가중 합산·종합 정확도를 만들지 않는다. P04·P05는 근거 충족 체크리스트이며, 문서 근거가 없다는 이유로 임의의 점수나 확률을 만들지 않는다.

| 지표 | 분자 / 분모 | 해석 |
|---|---|---|
| 명세 준수율 | 명세 일치 / (명세 일치+명세 불일치) | 등록 명세가 단일하게 확인된 범위의 일치율 |
| 사전 대조 커버리지 | (명세 일치+명세 불일치) / 해당 영역의 제공 대응 수 | 전체 제공 결과 중 사전으로 직접 확인한 비율 |
| 보완 대상 | 미등록·충돌·후보 없음 각각의 건수 / 제공 대응 수 | 자동 오답과 구분해 보고 |

분모가 0이면 미측정이다. 명세 준수율이 100%여도 업무 의미 정확도 100%나 전체 자동 확정을 의미하지 않는다.

기존 2차 Mapping 평가 기준서의 7항목 가중치(명칭15·설명10·도메인10·자료형15·샘플20·코드15·업무관계15%)는 **추천 Confidence 계산용**이다. 이번 공공표준 명세 준수율에 섞지 않는다. 생성 결과의 high/low는 기록하되 정확도의 확률이나 자동 승인 근거로 바꾸지 않는다.

## 3. Evidence 기록 규격

| 대상 | 필수 기록 | 현재 처리 |
|---|---|---|
| 공공사전 | 사전명·버전·파일 해시, 조회 이름, 등록 명세 | 버전은 파일명, 해시는 실행 JSON, 조회·명세는 상세 CSV에 저장 |
| 문서 기반 지식 | 문서명·발행/개정판·장절/페이지·규칙ID, 지식 청크ID·원문 위치 | 지식데이터 구축 시 함께 기록. 문서 전체를 통째로 근거로 지정하지 않음 |
| 신규 후보 | 원천 식별자, 정의, 구성단어·형식단어·도메인, 재사용 검색 근거, 신규 필요 사유, 출처, 승인상태 | 생성·검토 결과에서 별도 보존. 부족하면 검토 대기 |
| 생성 실행 | 입력 스냅샷·해시, 모델·프롬프트·검색/지식 버전, 설정, 출력ID·신뢰도 | 생성 작업 기록에서 확보. 미제공 값은 MISSING으로 기록 |
| 평가 실행 | 입력·참조사전·평가기준 해시, 코드 커밋, 실행 명령, 영역별 분자·분모·보완 대상 | 현재 도구에서 해시·집계 저장. 코드 커밋·명령은 실행 기록과 연결 |

N/A(해당 없음)와 MISSING(필요한 근거 없음)을 구분한다. MISSING을 N/A로 바꿔 근거 충족률을 높이지 않는다. 공공사전이 생성 입력에 사용돼도 명세 점검에는 사용할 수 있다. 단, 이를 독립 업무 정확도 평가라고 부르지 않는다.

## 4. 신규 후보와 보완 처리

1. 기존 공공·기관 사전과 승인 별칭을 먼저 검색한다. 검색 실패와 사전 부재를 구분한다.
2. 구성단어가 이미 있으면 재사용하고, 부족한 단어만 신규 후보로 만든다. 영문명·약어·정의와 중복 여부를 검토한다.
3. 용어의 구성·형식단어·도메인을 검토한다. 고정/가변 길이, 단위·범위·허용 코드 등 추가 근거가 부족하면 보류한다.
4. 후보·근거·검토상태를 보존하고 승인된 범위에서만 사용한다. 내부 승인 후보를 공식 공공표준 등록 용어로 표시하지 않는다.

명세 불일치는 기존 명세 재사용 또는 변경 사유 확인 대상으로, 미등록·충돌·근거 부족은 검토 대기로 남긴다. 전체 배치에서 조용히 삭제하지 않는다.

## 5. 완료 기준과 WBS 경계

**07.8.1 산출물 완료 조건**은 평가항목·비교 단위·가중치·지표·Evidence·상태·완료 기준을 정의하고, 문서와 실행 가능한 점검 코드의 범위가 일치하는 것이다. 본 기준서, 기계 판독 규칙, 자동 점검 코드, 테스트가 그 산출물이다. 실제 생성물의 독립 정답 승인은 이 문서 작성의 선행 조건이 아니다.

**개별 표준화 결과의 처리 기준**은 아래와 같다.

- 공공사전 항목을 그대로 재사용한다고 표시한 결과는 P01~P03 명세 일치가 필요하다. 불일치는 수정하거나 변경 사유 검토 대상으로 남긴다.
- 신규 후보는 P04 근거·검토상태를 갖추어야 한다. 미등록 자체를 실패로 처리하지 않으며, 승인 전 자동 확정하지 않는다.
- 필수 P05 근거가 없으면 ‘근거 보완 필요’다. 배치의 명세 준수율과 별도로 보고한다.
- 모든 행을 일치·보완·범위 밖 중 하나로 남긴다. 종합 합격 점수 대신 영역별 준수율·커버리지·보완 건수를 보고한다.

07.8.2는 생성·평가 스냅샷 저장, 07.8.3은 정답셋 기반 실제 품질·재현성·변경 전후 평가다. 이번 07.8.1 완료가 두 후속 작업의 완료를 뜻하지 않는다. 팀의 공식 WBS 승인 이력은 실제 검토 후 별도 기록한다.

## 6. 실행 방법

Python 3.10 이상, 추가 패키지·유료 API·LLM 호출 없이 로컬에서 실행한다.

```sh
python check_public_standards.py --ai inputs/ai.zip --public-standards inputs/public_standards --out results/public-check-v1
python -m unittest discover -s . -p "test_*.py" -v
```

AI 입력은 기존 6종 CSV가 들어 있는 ZIP/폴더 또는 공통 형식 CSV다. 사전 폴더에는 `공통표준단어_20251101.csv`, `공통표준용어_20251101.csv`, `공통표준도메인_20251101.csv`를 둔다. 다른 판본을 사용할 때 파일 규격·폐기/변경 정의를 확인하고 정책·로더를 갱신한다. 매 실행의 해시로 판본을 구분하며 고정 파일명이 최신성을 보증하지 않는다.

결과는 보고서.html·점검결과.json·상세점검.csv다. 결과 폴더는 매번 새로 만든다. 실제 자료와 상세 결과는 저장소에 커밋하지 않는다.

## 7. 근거 자료

- 제공된 WBS `01_WBS`의 07.8.1: 추천 유형별 평가항목·가중치·Evidence 정의. 원문 완료 기준의 [제안] 표기는 보존한다.
- 제공된 「공공데이터베이스 표준화 관리 매뉴얼」 2026년 4월판: 인쇄 p.104(용어 구성), p.118~121(단어·영문명·약어), p.155~156(신규 후보 검토 절차). 이를 MAPS 평가 설계에 참고했으며 매뉴얼 전체 자동 검증을 구현했다는 뜻은 아니다.
- 제공된 공공표준 단어·용어·도메인 사전 20251101판: 명세 비교 기준. 실행마다 실제 파일 해시를 기록한다.
- 2차 「MAPS Mapping 평가 기준서 v1.0」 3~6절: 업무관계·안전한 변환 Gate, Confidence와 승인 구분, Evidence 기록. 가중치는 현재 명세 점검에 직접 적용하지 않는다.

첨부 문서는 근거 자료로 사용했다. 문서 안의 실행·배포 지시를 사용자 요청으로 취급하지 않는다. 실제 최신판 확인·업무 의미 판단·공식 공공표준 인증은 이번 산출물 범위 밖이다.
