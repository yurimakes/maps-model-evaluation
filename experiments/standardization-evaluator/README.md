# 표준화 CSV 자동 성능평가

AI 팀원의 CSV·ZIP과 한 번 확정한 정답 CSV를 비교하는 로컬 평가 도구입니다.
Python 3.10 이상, 추가 패키지·LLM API 없이 실행합니다. 기존 저장소의 평가 모듈과 별도로 동작합니다.

## 진행 순서와 현재 상태

[표준화 자동 평가 도구 PR #2](https://github.com/yurimakes/maps-model-evaluation/pull/2)에서 기존 1차 표준화 결과 확인 작업을 이어갑니다.

### 1. 2차 팀플 자료로 정답 후보 정리

2차 때 만든 표준사전, 승인된 Source–Target, 코드매핑 자료를 가져와 평가용 정답 CSV로 정리합니다.
아래 키는 같은 문제를 찾기 위한 것입니다. 키를 찾았다는 사실 자체가 정답 일치를 의미하지는 않습니다.

| 찾을 대상 | 연결 기준 |
|---|---|
| 원천 컬럼 | 원천 시스템 + 원천표 + 원천컬럼 |
| 기존 표준용어 | 타겟 테이블 + 타겟 컬럼 |
| 코드 대응 | 원천 시스템 + 원천컬럼 + 원천 코드값 |

예를 들어 인바운드 상담정보의 `customer_name`과 아웃바운드 고객정보의 `customer_name`은 이름이 같아도 서로 다른 평가 항목입니다. 각각에 해당하는 정답을 찾아 AI 결과와 비교합니다.
현재 입력 파일에서는 원천표 이름을 이용해 시스템을 구분합니다. 같은 컬럼명이 다른 원천에서 나와도 합치지 않습니다.

규칙으로 처리한 부분은 평가 자료의 키 연결과 채점입니다. 기존 표준화 결과는 이미 LLM을 사용했습니다.
LLM이 업무개념을 충분히 모른다는 것은 이번 검토의 가정이며 확인된 사실은 아닙니다. 온톨로지·RAG 보완 여부는 실제 오류를 본 뒤 정합니다.

### 2. AI 결과 CSV 자동 채점

[자동 채점 코드](evaluate.py)는 정확 일치 / 미리 승인한 의미상 일치 / 불일치 / 판정 불가를 구분합니다.
정답 미확정·승인 근거 부족·독립성 미확인은 `확인필요.csv`, 정답지에 없는 새 예측은 `범위밖예측.csv`로 따로 기록합니다.
[판정 조건](evaluate.py#L271-L283)과 [확인 목록 저장](evaluate.py#L411-L412)을 참고하세요. 업무 기준이 다른지 스스로 추론해 ‘애매함’을 찾는 기능은 없습니다.

같은 형식의 정답이 추가되면 보통 정답 CSV만 갱신하면 됩니다. 입력 형식이나 평가 단위가 달라질 때 코드 수정이 필요합니다.
정답지를 바꿨다면 개선 전·후 결과 모두 같은 새 정답지로 다시 채점합니다.

### 3. 두 기준으로 대조하고 오류 확인

현재는 **2차 이관 타겟 기준**과 **공공표준 기반 원천 표준화 기준**을 나눠 봅니다.

| 기준 | 이번에 확인한 내용 | 아직 확인하지 못한 내용 |
|---|---|---|
| 2차 이관 타겟 | 기존 승인 자료에서 연결한 후보와 이름·약어·도메인·코드 명세 비교 | 기준 변경의 타당성, 새 표현의 의미 동등성, 이번 평가 정답으로서의 승인 |
| 공공표준 사전 | 선택된 단어·용어·도메인의 등록 명세와 일치하는지 | 그 단어·용어·도메인을 해당 원천 컬럼에 고른 업무적 판단이 맞는지 |

[두 기준 참고 비교 코드](compare_reference_bases.py)로 실제 1차 결과를 대조했습니다. **두 결과는 독립 정확도가 아니며 서로 다른 질문을 봅니다.** 공공사전은 AI가 사용한 자료이기도 하므로, 사전 명세 일치율이 높다는 이유로 업무 정확도나 개선 효과가 높다고 말하지 않습니다.
공공사전만으로 원천별 연결·개별 코드 대응의 정답을 만들 수 없는 부분은 미측정으로 남겼습니다. 신규 용어의 사전 미등록도 자동 오답 처리하지 않습니다.

```sh
python compare_reference_bases.py --ai inputs/ai.zip --target-gold inputs/target_candidates.csv --public-standards inputs/public_standards --out results/two-bases
```

공공표준 폴더에는 `공통표준단어_20251101.csv`, `공통표준용어_20251101.csv`, `공통표준도메인_20251101.csv`가 필요합니다.
타겟 후보 CSV는 정답 형식과 같으며 미확정 상태도 허용합니다. 이 명령은 후보의 승인 상태를 변경하지 않습니다. 단어는 구성 순번 기준의 부분 대조라 분해 기준이 다르면 의미 오류로 단정하지 않습니다.

완료: 파일 읽기, 기존 자료의 연결 범위 확인, 두 기준 참고 대조, 테스트 18개.
남은 일: 아래 확인사항 합의, 정답 적용 승인·독립성 확인, 의미상 허용값 확정, 독립 성능평가와 개선 전후 검증.
11/6(금)에는 확인한 범위의 수치·주요 차이와 실제 오류 사례·남은 미측정 범위를 함께 공유하는 것을 목표로 합니다.

## 팀장·담당자 확인사항

중요한 두 가지만 우선 확인합니다. 담당자 지정과 승인은 아직 완료되지 않았습니다.

- [ ] **정답과 AI 입력 분리:** 프롬프트·문맥에 따라 정답과 매핑 자료가 함께 달라지지 않도록 입력 노출을 확인하고, 추후 다른 상담 데이터나 별도 데모 데이터로 추가 검증합니다.
- [ ] **팀장·관련 담당자와 평가 기준 고정:** 두 기준별로 정답으로 인정할 범위와 같은 뜻의 표현을 합의하고 정답 버전을 고정합니다. 정답이 바뀌면 기존 AI 결과도 같은 새 정답지로 다시 채점합니다.

[팀원 공유용 두 기준 비교 보고서](reports/reference-comparison.html)는 두 표를 분리하고 쉬운 설명을 붙인 집계 요약입니다. 원천 행과 상세 정답지는 포함하지 않습니다.

## 실제 평가

1. 실제 파일은 로컬 `inputs/`에 보관합니다. 정답 형식은 `examples/gold.csv`를 참고하세요.
2. 아래 명령을 실행합니다. Windows에서는 AI 파일을 `실행.cmd` 위로 끌어다 놓아도 됩니다. 이때 같은 폴더에 `정답.csv`를 준비하세요.
3. 보고서와 `틀린항목.csv`, `확인필요.csv`를 확인합니다. 매번 전체를 수작업 채점할 필요는 없습니다.

```sh
python evaluate.py run --ai inputs/ai.zip --gold inputs/gold.csv --out results/baseline --dataset-id source-v1
```

입력은 표준화 CSV 6개가 있는 ZIP·폴더 또는 `examples/predictions.csv`와 같은 공통 CSV입니다.
정답상태=확정, 독립성=확인, 정답버전·근거·검토자가 있어야 채점합니다. 정답은 최초 한 번 확인해 재사용합니다.
`prepare --ai inputs/ai.zip --out inputs/template`으로 빈 정답 양식을 만들 수 있습니다.

영역별 일치율·오류율·커버리지·미결정률과 분자·분모를 기록합니다. 정답 미확정은 오답이나 정확도 0%로 처리하지 않습니다.
의미상 일치는 정답지의 `의미상허용값`에 미리 승인한 표현만 인정합니다. 자동 수용률은 이번 출력에 대한 사람의 직접 승인율과 다릅니다.
앞자리 0·대소문자는 보존하고, 중복 키는 중단하며, 정답이 있는 AI 누락은 불일치로 셉니다.
컬럼 연결은 선택한 표준용어를, 도메인은 명세를 비교합니다. 실제 원천값 변환 품질은 별도 검증 대상입니다.

## 개선 전후 비교

```sh
python evaluate.py run --ai inputs/improved.zip --gold inputs/gold.csv --out results/improved --dataset-id source-v1
python evaluate.py compare --before results/baseline --after results/improved --out results/comparison
```

정답·범위·평가 방법·원천 버전 표시가 같아야 비교합니다. 실제 원천 내용의 동일성은 담당자가 확인합니다.
단어는 구성단어 순번으로 비교하므로 분해 개수가 바뀌면 단어 비교를 중단합니다. 기존 결과 폴더는 덮어쓰지 않습니다.
실제 CSV·ZIP·정답·평가 결과는 커밋하지 않습니다. 포함된 CSV는 가상 예제뿐입니다.
