# MAPS | AI 데이터 매핑 고도화 실험

**MAPS**는 서로 다른 시스템의 Source 데이터와 Target 데이터 모델을 연결하는 데이터 마이그레이션 지원 프로젝트다. 시스템마다 컬럼명·자료형·업무 의미가 다르기 때문에, 데이터를 옮기기 전에는 **어떤 컬럼을 어디로 이관하고 어떻게 변환할지** 정의해야 한다.

이 저장소는 두 가지 문제를 구분해 연구한다.

- **매핑 추천:** 이미 정의된 표준·업무 지식과 매핑 관계를 활용할 때 Source–Target 연결을 얼마나 정확히 제안할 수 있는가?
- **매핑정의서 작성:** 승인된 매핑 관계가 없는 상태에서 Target 선택·이관 여부·변환 규칙의 초안을 얼마나 자동으로 작성할 수 있는가?

현재까지 세 가지 실험을 수행했다. **사전학습 모델 비교 → 그래프 기반 관계 탐색 → 매핑정의서 자동 작성 기준선**으로 범위를 확장했다. 각 실험의 평가 데이터와 지표가 다르므로 아래 숫자를 하나의 성능 순위로 비교하지 않는다.

|---|---|---|---|

## 01. 사전학습 모델 비교 — 컬럼 매칭의 기본 성능

### 문제 정의

데이터베이스 간 컬럼 이름이 다르거나 약어가 사용되면 단순 문자열 일치만으로는 Target을 선택하기 어렵다. **컬럼 설명과 자료형을 추가하거나, 의미를 표현하는 임베딩 모델을 변경하면 실제 매핑 판단이 개선되는지** 확인했다.

### 방법

- MPNet, 다국어 E5, 한국어 SRoBERTa의 공개 사전학습 가중치를 CPU에서 실제 실행했다. 별도 파인튜닝은 하지 않았다.
- Magneto 공개 구현의 **비LLM 스키마 매칭 구성**을 사용해 컬럼명만 제공하는 조건과 설명·자료형을 추가하는 조건을 비교했다.
- 동일한 평가 범위에서 매핑 정밀도·재현율·F1을 계산하고, 이관 제외 판단도 함께 확인했다.

### 결과

**동일한 93개 평가 질문(매핑 44개·이관 제외 49개)에서 관찰한 매핑 F1**

| 방법 | F1 |
|---|---:|
| MPNet · 컬럼명만 사용 | 43.2% |
| MPNet · 컬럼명 + 설명 + 자료형 | 65.2% |
| 다국어 E5 · 동일한 메타데이터 | **65.9%** |
| 한국어 SRoBERTa · 동일한 메타데이터 | 40.9% |

**해석:** 모델을 바꾸는 것보다 **적절한 메타데이터를 제공하는 효과가 크게 관찰**됐다. 동일 메타데이터에서 E5와 MPNet의 F1 차이는 작아, 이 결과만으로 E5가 일반적으로 우수하다고 결론 내리지 않는다.

별도로 기존 RAG 출력이 남아 있는 18개 질문에서는 저장된 기존 출력과 신규 모델을 비교했다. 이 비교는 전체 93개 질문에 대한 기존 RAG의 최종 성능 비교가 아니다. 본 실험은 LLM 재정렬·운영 환경 마이그레이션·새로운 원천에 대한 일반화 성능을 입증하지 않는다.

## 02. 그래프·온톨로지 실험 — 관계 정보의 추가 가치

### 문제 정의

컬럼명이 비슷해도 업무 의미가 다르면 잘못된 Target을 선택할 수 있다. **표준용어·단어·도메인 관계와 다른 Source 시스템에서 승인된 매핑 이력**이 이 문제를 개선하는지 검증했다.

### 방법

- 표준 개념과 Target 컬럼의 관계를 경량 그래프로 구성하고, 검색 점수에 관계 기반 점수를 결합했다.
- 다른 원천의 승인 이력을 활용하는 조건과 그래프를 추가하는 조건을 구분했다.
- 5개 Source 시스템을 번갈아 평가에서 제외하는 방식으로 해당 시스템의 정답 연결이 추천에 직접 사용되지 않도록 구성했다.
- **114개 평가 질문, 매핑 대상 65개, 승인 관계 68쌍, 이관 제외 49개, Target 후보 78개**를 평가했다.

### 결과

| 방법 | Top-1 적중률 | Top-5 적중률 | 매핑 F1 |
|---|---:|---:|---:|
| 메타데이터 TF-IDF | 41.5% | 75.4% | 36.6% |
| 기존 승인 이력 결합 | 64.6% | 89.2% | **54.0%** |
| 용어·단어·도메인 그래프 | 66.2% | 83.1% | 42.9% |
| 그래프 + 다른 원천 승인 이력 | **69.2%** | **92.3%** | 51.8% |

**해석:** 그래프와 이력을 결합한 경우 Top-1·Top-5 후보 적중률은 개선됐지만, **매핑 F1은 승인 이력만 사용한 방식보다 2.2%p 낮았다.** 따라서 그래프 도입으로 전체 매핑 정확도가 향상됐다고 주장할 수 없다.

Top-K 적중률은 올바른 후보가 추천 목록에 포함됐는지 측정하는 지표다. **Top-K 개선은 곧바로 확정 매핑의 정확도나 실제 이관 성공을 의미하지 않는다.** 또한 평가에 사용한 표준 지식과 규칙은 이미 프로젝트 자료를 참고해 구성되어 있어 독립된 외부 데이터 검증이 필요하다.

[실험 코드와 결과 확인](experiments/maps-graph-lab/)

## 03. 매핑정의서 초안 자동 생성 — 기존 매핑 관계 없이 시작하기

### 문제 정의

앞의 두 실험은 주로 **Source–Target 매핑 후보를 더 잘 찾는 방법**을 다뤘다. 그러나 실제 데이터 마이그레이션에는 연결 후보뿐 아니라 **이관 여부·변환 방식·예외 처리**를 명시한 매핑정의서가 필요하다.

세 번째 실험에서는 기존 승인 매핑정의서를 생성 알고리즘에 제공하지 않고, Source·Target 메타데이터만으로 초안을 작성할 수 있는 범위를 확인했다.

### 방법

- 컬럼명 문자 n-gram TF-IDF, 약어 유사도, 컬럼 설명 유사도를 결합해 Target 후보를 계산했다.
- 자료형 호환성과 테이블 단위의 유사도를 반영하고, 점수·후보 간 차이·근거의 충분성을 검사했다.
- 명시적 근거로 판단할 수 있는 경우에만 `MIGRATE` 및 `COPY`·`FORMAT`을 제안하고, 정보가 부족하면 `REVIEW`로 보류했다.
- 구현 코드는 Claude의 개발 보조를 받아 작성했지만, **실제 매핑 추론은 외부 LLM을 호출하지 않는 Python 규칙·유사도 알고리즘**으로 수행했다.

### 결과

**Source 140개 컬럼 / Target 78개 컬럼에 대한 초안 생성**

| 판정 | 건수 | 의미 |
|---|---:|---|
| `MIGRATE` | **4 (2.9%)** | COPY 3건·FORMAT 1건을 자동 작성한 *승인 전 후보* |
| `REVIEW` · Target 후보 식별 | 8 (5.7%) | Target을 제안했으나 변환 규칙 미확정 |
| `REVIEW` · Target 미확정 | 128 (91.4%) | 추가 업무 근거나 검토 필요 |
| `EXCLUDE` | 0 | 명시적인 제외 규칙이 입력되지 않음 |

전체 140개에 대한 JSON 초안은 생성했지만, **변환 규칙까지 자동 작성된 항목은 4개에 불과**했다. 일부 자동 이관 후보에도 미확정 업무 조건이 있어 실무 승인으로 간주할 수 없다.

합성 단위 테스트 **28/28**, 출력 구조 검증 **21/21**을 통과했다. 이는 코드 동작과 출력 형식에 관한 검증이며 **기존 승인 매핑과의 일치도, 실제 변환값 정확도, 전문가 수용률은 아직 측정하지 않았다.**

**해석:** 기존 검색만으로는 완성된 매핑정의서를 자동 작성하기 어렵다는 한계가 확인됐다. 특히 코드 대응표·식별자 정책·복잡한 변환 규칙처럼 업무 지식이 필요한 부분은 단순 유사도로 확정할 수 없다.

[실험 코드와 합성 테스트 확인 — PR #1 검토 중](https://github.com/yurimakes/maps-model-evaluation/tree/feature/exp1-rule-baseline-reviewed/experiments/mapping-spec-generation/exp1-rule-baseline/)

## 검증 범위와 다음 단계

현재의 수치는 각각의 **서로 다른 평가 범위**에서 얻은 결과다. 93개 질문의 사전학습 모델 비교, 114개 질문의 그래프 실험, 140개 Source의 정의서 초안 생성 결과를 하나의 정확도 비교표로 합산하지 않는다. 이전에 저장된 RAG 응답의 재채점, 실제 사전학습 모델 추론, 규칙 기반 초안 생성도 구분한다.

세 번째 실험의 후속 단계는 **매핑정의서 초안을 기존 승인 정의서와 독립적으로 대조**하는 것이다. 이때 Source 식별자 차이를 정리하고 Target 매핑 일치도, 이관 여부, 변환 연산을 나눠 평가한다. 이후 실제 변환 결과를 검증할 수 있는 사례에 한해 실행 정확도를 확인하고, 오류 유형에 따라 논문 기반 SQL·변환 규칙 생성 방식을 추가 검토한다.

여기 기록한 성능은 특정 평가셋에서 관찰한 결과이며, 현업 전체에서의 정확도·마이그레이션 완료율·업무시간 절감 효과를 의미하지 않는다.

### 실험 01 — 사전학습 모델과 메타데이터 입력 비교

**연구 질문:** 모델 교체 효과가 설명·자료형, 후보 범위, 보류 기준을 통제한 뒤에도 유지되는가?

1. 기존 93문항 평가와 별도의 18문항 저장 응답 비교를 분리하고, 입력·후보·정답·모델 revision을 고정한다.
2. 동일 조건에서 컬럼명만 사용, 컬럼명+설명, 컬럼명+설명+자료형의 기여를 분리하고 MPNet·다국어 E5·한국어 SRoBERTa의 실제 추론 결과를 비교한다.
3. 원천 시스템별 오류를 업무 의미 오인, 약어, 메타데이터 부족, 자료형 충돌, 이관 제외 오판으로 분류한다.
4. 매핑 F1·Top-1·Top-K·보류율과 실측 추론시간을 별도로 기록한다. 비용은 실제 측정 가능한 범위만 보고한다.

**도입 판단:** 작은 모델 간 점수 차이를 일반적 우월성으로 해석하지 않는다. 메타데이터 보강만으로 충분하면 추가 모델 도입을 보류하고, 별도 원천에서 일반화 성능을 검증한다.

### 실험 02 — 경량 그래프의 추가 가치 검증

**연구 질문:** 표준 개념 그래프가 검색·사전·다른 원천 승인 이력만으로 얻는 성능보다 실제 매핑 결정을 개선하는가?

1. 기존 114질문·78후보 및 원천별 분리 평가를 유지하고 기본 검색, 승인 이력 추가, 그래프 추가, 그래프+이력을 비교한다.
2. 그래프+이력에서 Top-1·Top-5가 좋아졌지만 매핑 F1은 승인 이력 단독보다 낮았던 원인을 사례별로 분석한다. 잘못된 고확신 추천과 보류 임계값을 우선 살핀다.
3. 그래프의 관계 유형·업무 제약·근거를 한꺼번에 늘리지 않고 하나씩 추가해 효과와 처리 부담을 측정한다.
4. 별도 원천에서 매핑 정밀도·재현율·F1·Top-K·보류율을 측정하며 소표본·원천 간 의존성의 불확실성을 보고한다.

**도입 판단:** 후보 탐색에만 이득이 있으면 해당 단계로 활용 범위를 제한한다. 단순 기준선보다 최종 매핑 품질이나 검토 효율의 이익이 확인되지 않으면 핵심 경로 도입을 보류한다. 신규 클라우드 그래프 서비스는 전제하지 않는다.

### 실험 03 — 매핑정의서 초안 검증과 후속 생성 방법

**연구 질문:** 기존 승인 매핑정의서를 생성 입력으로 사용하지 않고 Target 선택, 이관 여부, 변환 연산을 얼마나 정확히 초안화하는가?

1. 현재 규칙·유사도 기반 결과인 Source 140개, Target 78개, MIGRATE 4개, REVIEW 136개, EXCLUDE 0개를 **정확도가 아닌 기준선 출력**으로 고정한다. 구현은 현재 별도 검토 PR에 있으며 main에 병합되었다고 간주하지 않는다.
2. 정답 데이터를 생성 입력과 분리한 후 Source 식별자를 정렬하고 평가 가능한 항목과 분모를 확정한다. REVIEW 중 Target만 식별된 사례는 포함/제외 조건을 모두 채점한다.
3. Target 쌍 Precision·Recall·F1, 이관/제외/보류 판단, 자동 확정률·오확정률, COPY·FORMAT 등 변환 연산과 인자 일치를 별도로 평가한다.
4. 오류를 업무 의미 오인, 코드 대응표 부재, 식별자 정책, 자료형·형식, 근거 부족으로 구분하고 먼저 사전·검색·규칙의 최소 보완 효과를 확인한다.
5. 그다음 필요한 항목에 한해 LLM 또는 논문 기반 SQL·변환 규칙 생성 기법을 **같은 입력·출력 계약의 별도 조건**으로 비교한다. 참조 정답을 프롬프트·검색 입력에 제공하지 않으며 근거·보류·비용·재현성을 평가한다. 실제 값과 기대 출력이 준비된 일부 사례에서만 변환 실행 정확도를 측정한다.

**도입 판단:** MIGRATE 건수 증가만으로 개선이라 판단하지 않는다. 잘못된 자동 확정이 줄고, 정답 대조와 검토에서 충분한 이득이 확인될 때만 자동화 범위를 확대한다.

### 실험 04 — 상담 Raw 데이터에서 Target 테이블 설계까지 (신규·최우선)

**업무 목표:** 상담 데이터셋 **1종**을 입력해 Raw 데이터로부터 표준화와 Target 테이블 설계 초안까지 AI가 지원할 수 있는 범위를 **2026-11-06까지 검증**한다. 단순 표준사전 검색이나 후보 추천에서 끝나지 않는 end-to-end 흐름을 대상으로 한다.

| 단계 | 입력 | 생성·검증 대상 |
|---|---|---|
| ① Raw 구조 이해 | 사용 권한이 확인된 상담 원천의 스키마와 필요한 최소 샘플 | 데이터 유형, 컬럼·값 특성, 결측·코드 후보 분석 |
| ② 메타정보 추출 | Raw 프로파일링 결과 | 표준데이터/컬럼 메타정보, 명칭·설명·자료형·길이·NULL 여부 등의 초안 |
| ③ 표준 4종 도출 | Raw 분석과 컬럼 메타정보 | **표준단어·표준용어·표준도메인·표준코드** 후보, 정의·근거·보류 항목 |
| ④ Target 테이블 설계 | 도출한 표준 4종과 구조 제약 | 테이블·컬럼 구성, 자료형·길이·키·NULL 제약·코드 참조의 설계 초안 |
| ⑤ 독립 평가·검토 | 생성 결과를 고정한 후 별도 대조 자료 | 정합성·누락·오류·보류·검토 필요 사항과 재현 기록 |

**구현 기준:** 먼저 Python 프로파일링, 명시적 규칙, 허용된 표준사전 검색의 기준선을 확인한 뒤 의미 추론이 필요한 지점에만 모델·LLM을 추가한다. 생성물은 운영 표준이나 승인된 DDL이 아니라 검토 대상 초안으로 제공하고 근거·불확실성·보류 사유를 남긴다. 승인된 사전의 일반 규칙 활용과 평가 대상의 완성된 정답 입력 사용은 구분한다.

**평가 기준:** 표준 4종을 각각 평가하고, 메타정보 자료형·길이·제약 적합성 및 Target 테이블·컬럼 구조의 타당성, 코드 참조·키 제약을 별도 판정한다. 비교용 기존 수작업 결과는 생성 후 독립 대조한다. 정답이 유일하지 않은 설계는 검토자가 허용 범위를 정하고, 표본 수·분모·판정 불가 건수를 기록한다. DDL 텍스트 생성 성공 자체를 설계 정확도로 계산하지 않는다.

**1차 검증 일정(목표이며 변경 가능):**

- **10/30–11/01:** 상담 데이터 1종의 사용 범위·출력 계약과 정답 누출 방지 기준 확정, 단순 기준선 설정
- **11/02–11/04:** Raw 프로파일링 → 메타정보 → 표준 4종 → Target 테이블 설계까지 최소 흐름 구현, 단계별 오류 수집
- **11/05:** 독립 수작업 결과 대조, 미확정 사유와 재현성 점검
- **11/06:** 단계별 결과·평가 지표·실패 사례·도입 가능 범위와 남은 과제 정리

**범위 경계:** 이번 1차 실험은 Raw 기반 표준화와 Target 설계까지를 주 대상으로 한다. Bronze 적재, 운영 DQ 검사, 최종 Source–Target 매핑 승인, Gold 이관 실행은 실험 04의 자동화 성공 범위로 계산하지 않는다. 개인정보 자동 탐지·마스킹 및 음성 입력은 별도 필요성과 검증 조건이 확정되기 전까지 필수 구성으로 넣지 않는다.

### 공통 평가·보존 원칙

- 실험마다 과제·입력·정답·후보·지표·분모·실행 환경을 고정하고, **서로 다른 평가셋의 수치를 하나의 성능 순위로 합산하지 않는다.**
- 비교용 수작업·승인 결과는 생성 입력과 분리한다. 사용한 사전·규칙·이력의 설계 영향과 정답 누출 가능성을 확인한다.
- 원본 상담 행·개인 식별정보·비공개 업무 자료·실제 개별 예측·인증정보는 공개 저장소에 올리지 않는다. 공개 산출물은 비식별 기술 내용, 합성 예시, 집계 지표, 재현 절차로 한정한다.
- 기존 코드·이력·평가 기록을 보존한다. 신규 구현은 별도 실험 경로·브랜치에서 검토하며, main의 계획 변경은 실험 PR 병합이나 배포를 의미하지 않는다.
- 개선이 입증되지 않으면 도입을 보류한다. 전문가 수용률·검토시간 절감·실제 마이그레이션 성공률은 측정하지 않았다면 주장하지 않는다.
